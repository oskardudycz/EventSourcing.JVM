### Step-1. Metadata that is the JSON literal `null` still throws out of KurrentDB `read` and the subscription
Quote: `mapper.readValue(raw, new TypeReference<Map<String, Object>>() {}).forEach(...)` inside `try { ... } catch (JacksonException e) { return Map.of(); }`. The new test covers only `[1,2]`.
Consequence: Jackson returns `null` for the bytes `null` (expected, not run), so `.forEach` throws `NullPointerException`, which the catch does not handle. An aggregate load fails and a subscription stops. This is the case the Q30 resolution ("not a JSON object is treated as no metadata") was meant to remove.
Belongs to: implementation
Resolution: open

### Step-2. `HttpCommandMetadataTests` passes without tracing or baggage
Quote: `assertThat(metadata).extracting(EventMetadata::correlationId).doesNotContainNull(); ... allSatisfy(each -> assertThat(each.causationId()).isEqualTo(each.correlationId()))`. Plan: "events appended by an HTTP command have a new `correlationId` and `causationId` equal to it".
Consequence: the in-memory store gives this result for every append outside a handler, even with `Tracer.NOOP`. The test checks neither that the id is a non-blank new id per request, nor that two requests differ. It does not guard the HTTP path it is named for. The inbound `baggage` header case is untested (not required by the earlier resolution). Low severity.
Belongs to: implementation
Resolution: open
