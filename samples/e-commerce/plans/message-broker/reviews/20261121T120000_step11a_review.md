### Step-1. The 2000 ms probe can collapse a section that is expanded but slow to render

Quote: diff: `const isExpanded = await expect(items.first()).toBeVisible({ timeout: 2000 }).then(() => true, () => false); if (!isExpanded) await header.click();`. Step: "waits until the page's sidebar has rendered before it reads the ... lists, so it doesn't fail when the machine is slow".
Consequence: if the section is expanded and its items need more than 2 s to render, the probe reports "collapsed" and the click closes it. The final `expect(items.first()).toBeVisible()` then fails with the same "element(s) not found" error the step removes. A click before hydration is lost the same way and nothing retries it. `.then(() => true, () => false)` also hides every other error. `spec.md` and `qa.md` do not decide this (Q32 only chooses a small fix), and the step's wording is clear, so it is tagged `implementation`.
Belongs to: implementation
Resolution: fixed: the 2 s probe and the timeout are gone; the function waits for the header, then keeps the original structural count check (Step-1, Step-2, Standards-1, Standards-2)
