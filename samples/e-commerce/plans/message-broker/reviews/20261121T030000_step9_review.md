### Step-7. The "every published type has a stable name" test works from a hand-written list

Quote: `ECommerceMessagesTests` uses `PublishedMessages.of(...)`, a manual list of 32 instances. The mapping has 33 entries. Decision under Step-5: "a test checks every type the modules publish has a stable name".
Consequence: when someone adds a record to a sealed `*Command` or `*ExternalEvent` and publishes it without a mapping entry, the test still passes. The failure shows only at runtime on Kafka, as the new `IllegalStateException`. Low severity.
Belongs to: implementation (derive the list from the permitted subclasses of the published sealed interfaces, or test that `PublishedMessages` covers them all).
Resolution: accepted: the list is the step 1 list that the coordinator told me to reuse; a new type without a mapping entry fails the publish with an error naming the type

### Step-8. The `IllegalStateException` from `typeNameOf` can happen mid-batch

Quote: in `KafkaMessageBus.publish`, the loop calls `serializer.write(message)` and `serializer.typeNameOf(...)` for each message and sends it in turn. Spec: publishing a type with no stable name "fails with an error naming the type".
Consequence: a batch with an unmapped type at position n > 0 is partly published before the error. No test runs a mixed batch. The old class-name fallback never threw, so this path is new. The publish-failure path in the same loop already had this property.
Belongs to: implementation (resolve all type names before the first send), or decide that the partial send is accepted. spec.md and qa.md do not decide it.
Resolution: fixed: `publish` serializes and names every message before the first send; test `batchWithAMessageTypeWithoutAStableNamePublishesNothing`
