### Step-1. No in-memory span exporter in tests
Quote: plan: "Tracing is on (...), with an in-memory span exporter in tests"; similar code `W:core/InMemorySpansConfiguration.java`. Diff: `TestTracing` builds `SdkTracerProvider.builder().build()` with no exporter; `build.gradle` adds `opentelemetry-sdk-testing`, `micrometer-tracing-test`, `spring-boot-micrometer-tracing-test`; no source uses `InMemorySpanExporter`.
Consequence: no test can read finished spans, and the Spring context has no test exporter bean. The three test dependencies are unused. Steps 8 and later need the exporter.
Belongs to: implementation
Resolution: open

### Step-2. The real Spring tracing set-up is never run by a test
Quote: `application.properties` sets the baggage `correlation.fields`, `remote-fields`, `tag-fields` and `sampling.probability=1.0`; `ECommerceApplicationConfig.messageContext(Tracer)` takes the Spring `Tracer`. `TestTracing` builds its own `OtelTracer` with `OtelBaggageManager(..., List.of(CORRELATION_ID, CAUSATION_ID), ...)`.
Consequence: the tests pass even when the properties are wrong. If a baggage field is not allowed in the real `Tracer`, every message gets a new `correlationId` and `causationId` falls back to it, with no test failing.
Belongs to: implementation
Resolution: open

### Step-3. The "HTTP command" test does not go through HTTP
Quote: plan: "aStepWithNothingToInheritGeneratesTheCorrelationId - events appended by an HTTP command have a new `correlationId` and `causationId` equal to it". The test calls `eventStore().append` directly.
Consequence: the path where a command with nothing to inherit gets a generated `correlationId` is unchecked. It also cannot show whether two appends in one request share a `correlationId` (see Standards-4).
Belongs to: implementation
Resolution: open

### Step-4. The saga redelivery test uses probe handlers
Quote: plan 35.2: "the payments and shipments handlers append on each delivery". `OrderSagaRedeliveryTests` binds its own `probe` queue with lambdas for `AuthorizePayment` and `ReserveStock`.
Consequence: the real payments and shipments subscribers are not in the test. The derived ids and publish order are guarded; the wiring of the real modules is not.
Belongs to: implementation
Resolution: open

### Step-5. Bus value inheritance has no direct test
Quote: `MessageContext.inheritForPublished` `.orElse(values)` path (no handled message gives a random id); `context.handling(values.messageId(), values.correlationId())` in the bus delivery. `InMemoryMessageBusTests` has no test of the five values.
Consequence: a wrong `correlationId` or `messageId` in the bus scope, or a non-random id for a publish with no handled message, passes. `aHandledMessagePassesItsCorrelationIdOnAndBecomesTheCause` covers only the store subscriber path, not the bus subscriber path.
Belongs to: implementation
Resolution: open

### Step-6. KurrentDB read of missing or non-string metadata is untested and undecided
Quote: `metadataOf`: `userMetadata.getOrDefault(EventSerializer.CORRELATION_ID, messageId)` and `getOrDefault(CAUSATION_ID, correlationId)`; `userMetadataOf`: `mapper.readValue(raw, new TypeReference<Map<String, String>>() {})`; `read` catches only `InterruptedException | ExecutionException`.
Consequence: no test reads an event stored without metadata (older events, other writers). A non-string value throws a Jackson exception out of `read` or a subscription callback. Spec says only that a step with no cause uses its own `correlationId`.
Belongs to: implementation
Resolution: open

### Step-7. 28.1 test checks `messageId` only as a valid UUID

Consequence: a `messageId` that changes between append and read is not caught. Low severity.
Belongs to: implementation
Resolution: open

### Standards-2. Abstract hook `assertSpanIdOf` has the same body in both subclasses
Quote: `InMemoryEventStoreMetadataTests.assertSpanIdOf` and `KurrentDBEventStoreMetadataTests.assertSpanIdOf` both: `assertThat(metadata.spanId()).isEqualTo(testSpan.context().spanId())`. AGENTS.md: "Prefer simple, easily removable code over premature abstractions."
Consequence: an abstract method that does not vary. It belongs as one assertion in the base class.
Belongs to: implementation
Resolution: open

### Standards-3. No-arg constructors and `MessageContext.untraced()` exist only for tests
Quote: `InMemoryEventStore()`, `InMemoryMessageBus()` and `MessageContext.untraced()` have no caller in `src/main`; about 15 tests use them (`ECommerceTests`, `ShipmentFacadeTests`, `AggregateStoreTests`, `InMemoryMessageBusTests`, `KurrentDBEventStoreTests`).
Consequence: three extra production entry points that reach the no-op Tracer, so those tests never exercise propagation. Low; a design call.
Belongs to: implementation
Resolution: open

### Standards-4. Each append outside a handler gets its own `correlationId`
Quote: `MessageContext.inherit()` calls `baggage(CORRELATION_ID).orElseGet(MessageContext::newId)` on every append and publish; nothing opens a step scope at the HTTP entry point.
Consequence: two appends in one HTTP request get unrelated `correlationId` values. Correct only if every command appends once. Low confidence; needs Oskar to confirm the intent.
Belongs to: implementation
Resolution: open

### Standards-5. `EventSerializer.serialize(Object, MessageValues)` copies the body of `serialize(Object)`

Consequence: a change to event-type naming in one and not the other. Nit.
