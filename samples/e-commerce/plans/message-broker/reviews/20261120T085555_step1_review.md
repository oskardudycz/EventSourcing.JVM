### Step-1. The 15.2 message list is typed by hand, so a new message type is never checked

Quote: diff `publishedMessages()` is a fixed `List.of(new PaymentCommand.AuthorizePayment(...), ... new ShoppingCartExternalEvent.ShoppingCartCheckedOut(...))`. Step: "for one instance of every message type the modules publish through the bus (the permitted types of `PaymentCommand`, `ShipmentCommand` and `OrderCommand` ...)". Criterion 15: "Every message type has an explicit route".
Consequence: someone adds a command to a sealed interface and publishes it without a route. `everyPublishedMessageTypeHasAChannelAndARoutingKey` stays green; the publish fails only at runtime.
Belongs to: implementation (the step names the permitted types as the source; compare the list against `getPermittedSubclasses()` of the three command interfaces, or assert every permitted type appears in the list).
Resolution: open

### Step-2. aCommandIsRoutedWithTheRoutingKeyOfItsEntity computes the expected key with the code under test

Quote: diff `assertThat(route.key()).isEqualTo(Urns.routingKeyOf(paymentId.value()))`. Step: "`CapturePayment` with payment `urn:ecommerce:payment:<uuid>` gets key `ecommerce.payment.<uuid>`".
Consequence: if the format of `Urns.routingKeyOf` changed, the test would still pass. The key format is what Kafka ordering and the queue patterns (`ecommerce.order.*`) depend on. The step's literal is never asserted.
Belongs to: implementation (use a known UUID and compare against the literal `"ecommerce.payment." + uuid`).
Resolution: open

### Step-3. Middleware no longer sees a message that fails to publish; neither plan nor spec says so

Quote: diff moves `for (var middleware : middlewares) middleware.accept(message);` from before `routeFor` to after the no-route and undeclared-channel checks. Spec line 310: middleware runs "for every message before subscribers". Step and spec only say the publish fails.
Consequence: before, middleware such as `MessageCatcher` saw an unrouted message. Now it sees nothing and the publish throws. A test that counts sent messages through `use(...)` would miss the failed one. No test covers either order. Searched spec.md and qa.md for "middleware": neither decides this case.
Belongs to: plan (add one line saying whether middleware runs for a message that fails to publish; if yes, move the loop back before the checks).
Resolution: open
