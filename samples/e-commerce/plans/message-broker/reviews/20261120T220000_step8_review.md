### Step-5. Routing consumer retries forever, with a 1 s interval

### Step-6. A record without a `messageId` header gets a random id

Quote: `Objects.requireNonNullElseGet(header(record, MESSAGE_ID), () -> UUID.randomUUID().toString())`. Spec line 54: "A message that a handler publishes gets an ID derived from the handled message, so a redelivered copy keeps the same ID."
Consequence: for a record without the header, such as a foreign producer's, each redelivery gets a new id, so the `causationId` and the derived ids of its published messages differ. Failing the record is the other possible choice. Neither the step, the spec nor the Q&A (searched) defines this case, and no test covers it.
Belongs to: spec
Resolution: accepted by the coordinator under Q30: the sample's buses always set `messageId`; a record without one comes from outside the sample, so a random id is acceptable. Listed for Oskar at the end of the run. Then stays, as decided.
