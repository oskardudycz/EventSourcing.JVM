### Step-1. 18.1 does not check "without retries"

Quote: Step: "it goes to the queue's dead-letter destination without retries AND the next message is handled". Test `bodyThatIsNotJsonGoesToTheDeadLetterQueueWithoutRetriesAndTheNextMessageIsHandled` asserts the DLQ body, the next message and `deadLettered() == 1`. The Kafka sibling also asserts `deliveryAttemptOf(deadLetters.getFirst())` is 1.
Consequence: if an unreadable message were retried with back-off, the test would still pass (the retry interval is 10 ms and the counter stays at 1). The same gap applies to 19.1, which checks only the `messageType` header.
Belongs to: implementation
Resolution: fixed: the 18.1 and 19.1 tests count failure-strategy decisions and assert `decisions` is 1, so a retry fails them
### Step-2. The plan text of 20.1 describes a scenario that cannot happen

Quote: Plan: "sets a policy `max-length=0` with `overflow=reject-publish` on the dead-letter queue ... asserts the message is still in the source queue". Test: two messages, 5 s `dead_letter_worker_publisher_confirm_timeout` on its own container, a 7 s window with source 1 and DLQ 1, then the policy is deleted and the DLQ holds 2.
Consequence: quorum reject-publish accepts the first dead letter and the worker retries the next only after the confirm timeout (2m48s by default). The test proves the intent (no dead letter is lost while the DLQ refuses it, production keeps the default timeout), so the deviation is accepted. The plan text must say two messages and the shortened timeout. `spec.md` 20.1 and `qa.md` do not decide the policy or the timeout.
Belongs to: plan
Resolution: fixed in plan r7 by the coordinator: 20.1 now describes the measured behaviour (the first dead letter is accepted; one message stays in the source queue; the confirm timeout is 5000 ms on the test's own server).

### Step-3. No RabbitMQ test for a batch with a message type without a stable name

Consequence: moving the preparation into the send loop would publish part of a batch and then throw, and no test would fail.
Belongs to: implementation
Resolution: fixed: `batchWithAMessageTypeWithoutAStableNamePublishesNothing` checks that a collector queue stays empty
### Step-4. Paths with no test, and silent drop of a message with no handler

Resolution: the no-handler drop is decided by spec 8.1; the interrupt case is accepted by the coordinator under Q30; the nack and ExecutionException branches of `awaitConfirm` have no test and no step text asks for one
