### Step-4. A retry after a concurrent write opens another step span
Consequence: one command can leave several `handle <Type>` spans.
Belongs to: spec
Resolution: accepted by the coordinator (Q30): the spec asks for one span per handler call, and each retry is a handler call.

### Step-5. `causationId` of events written by `continuing`
Consequence: the events get the handled command's `messageId`, or the correlationId with no consumer; the spec names only parent span and correlationId.
Belongs to: spec
Resolution: accepted by the coordinator (Q30): it matches the spec, which says `causationId` is the `messageId` of the handled message.

### Step-6. `continuing` also overrides a command that arrives with a purchase context

Belongs to: spec
Resolution: open: decision for Oskar, follow-up F2.
