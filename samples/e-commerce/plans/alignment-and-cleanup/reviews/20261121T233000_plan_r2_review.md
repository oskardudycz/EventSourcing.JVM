### Spec-1. The 9.1 test can't record `StockReleased`, and it leaves out two of the criterion's events

Quote: step 4 "a shipment goes through reserve, fulfillment request, sent, delivered and release".
Consequence: `Shipment.releaseStock` records nothing after `Delivered` (`isStockHeld` holds only for Reserved, FulfillmentRequested and FulfillmentRejected). The test also never records `FulfillmentRejected` or `ProductWasOutOfStock`, so a `referenceId` left on the first or removed from the second fails no test.
Belongs to: plan
Resolution: fixed in r3: three paths that can happen: reserve, request, reject, release; reserve, request, sent, delivered; out of stock.

### Steps-1. The 4.2 test leaves an unreadable event that blocks later KurrentDB subscriptions

Quote: step 3 "a stored event with the subscribed type name and broken data; ... after the data is readable again (or a following valid event on a fresh subscription) handling resumes".
Consequence: a new subscription starts from the start of `$all`. If the test uses a type other tests subscribe to (`ItemAdded`), every later KurrentDB subscription to it retries the broken event forever, in this run and, on the Compose KurrentDB, in every later run.
Belongs to: plan
Resolution: fixed in r3: the test uses a test-only event class that only it subscribes to, and asserts only what 4.2 states: retried, checkpoint not moved.

### Steps-2. The broker dead-letter tests go into a base whose subclasses can't observe dead letters, and the failure test classes already cover them

Quote: step 3 `BrokerMessageBusTests.aMessageOfAnUntrustedClassIsDeadLetteredAsUnreadable`, `...aMessageWithAnOldNameIsReadAsTheCurrentClass`; step 5 `BrokerMessageBusTests.aDeadLetteredMessageIsCountedUnderItsQueueName`.

Resolution: fixed in r3: 5.3, 5.4 and 13.1 stay in the existing failure tests, updated to `__TypeId__` and the queue tag; the three `BrokerMessageBusTests` tests are removed.
