### Step-1. Kafka trusts `java.lang` and `java.util` as well as the modules' packages (breaks 5.4)

Quote: diff, `KafkaMessageBus.typeMapperOf`: `typeMapper.addTrustedPackages(serializer.typeMapper().trustedPackages());`. Criterion 5.4: "GIVEN a message whose class name is outside the modules' packages WHEN a bus reads it THEN it is dead-lettered as unreadable."
Consequence: `DefaultJacksonJavaTypeMapper` starts with `java.util` and `java.lang` trusted, and `addTrustedPackages` only adds. RabbitMQ's `setTrustedPackages` replaces the defaults. A Kafka record with type id `java.util.ArrayList` is created, not dead-lettered, while `isKnown` calls it unknown, so the tag and the deserializer disagree. The test `typeOutsideTheSamplesPackageIsNotCreatedAndIsDeadLettered` uses `java.lang.ProcessBuilder`, which probably fails in Jackson, so it passes without proving the trust rule. Needs a test with `java.util.ArrayList` on both brokers.
Belongs to: implementation
Resolution: fixed: both broker converters check `serializer.isKnown(typeName)` first; `aJavaUtilTypeIsDeadLetteredInsteadOfRead` on Kafka and RabbitMQ (confirmed by `20261122T150000_step4_review.md`).

### Step-2. A real handled message is detected by `causationId == correlationId`

Quote: diff, `MessageContext.inheritForPublished`: `if (values.causationId().equals(values.correlationId())) return values;`. Spec line 169: "A published message's id is derived only from a real handled message id; with none (a `continuing` scope without baggage), it is random."
Consequence: `KurrentDBEventStore.metadataOf` sets `correlationId = messageId` for an event without stored metadata, so a handler of that event gets a random id on publish. A redelivery then publishes a duplicate with a new id. The spec decides the rule ("a real handled message id"); the code uses a proxy that misses this case. Also, `derivedId` hashes the class name, not a module's explicit name, while Terms define the type name to include explicit names; decide which is meant. No test covers the derived or the random branch (the step review checks them, so the missing test is not a finding by itself, but the branch above is wrong).
Belongs to: implementation
Resolution: fixed: `MessageContext` keeps the handled message id in its own `handledMessageId` baggage; `InMemoryMessageBusValuesTests` covers the derived, random and redelivery cases.

### Step-3. Branches for an unknown name with a dot and for unreadable metadata have no test

Quote: diff, `MessageTypeMapper.trustedClassOf`: `catch (ClassNotFoundException e) { return Optional.empty(); }`; `PostgreSQLEventStore.eventOf`: `catch (JacksonException e) { throw new UnreadableMessageException(message.type(), e); }`.
Consequence: the 2.7 and 4.3 tests use names without a dot, so they never reach `Class.forName`; a trusted package with a missing class (a renamed or removed event, the realistic case for 4.3) is untested on the mapper and on every store. Unreadable metadata on PostgreSQL is untested.
Belongs to: implementation
Resolution: fixed: `DurableEventStoreTests.readingAStreamWithATrustedPackageButNoClassFailsNamingTheType` and `PostgreSQLEventStoreTests.readingAnEventWithUnreadableMetadataFailsNamingTheType`.

### Standards-2. Broker trust may be wider than the mapper's rule, while the README presents one rule

Quote: `trustedClassOf` matches `trustedPackages.contains(typeName.substring(0, lastDot))` (exact package). README: "lists the packages that hold its messages, one by one, and a reader creates only classes from those packages". Brokers pass the same list to Spring's mappers.
Consequence: Spring's mappers may also trust sub-packages (prefix match), so a name in `payments.authorization` could be readable on a bus and unreadable from a store, with the dead-letter tag saying `unknown`. No test uses a sub-package name. Together with Step-1, the broker trust list must equal the mapper's list.
Belongs to: implementation
Resolution: accepted: Spring Kafka 4.1.2 `DefaultJacksonJavaTypeMapper.isTrustedPackage` and Spring AMQP 4.1.2 `DefaultClassMapper.isTrustedPackage` match the package exactly; the `isKnown` check makes the mapper's rule the single rule.
