### Q&A-1. The spec deletes `getAndUpdate(id, expectedVersion, handle)`, but no change in the shop's core forces that

Quote: "loses the methods only the shop used (`getAndUpdateContinuingTrace`, `getAndUpdate(id, expectedVersion, handle)` and their helpers)"; "adapted to the new event store types only".
Consequence: Q11 allows changes only where the shop's core forces them; this overload compiles once it uses `ExpectedStreamVersion`. Two readings remain, and two tests depend on it.
Belongs to: qa
Resolution: fixed in r5 (coordinator, under Q11 "only align what's needed in core"): the overload stays, adapted to `ExpectedStreamVersion`, with its two tests; only `getAndUpdateContinuingTrace` and what only it uses are deleted.

### Quality-1. Kept `AggregateStoreTests`: no type mapping for its test-only events

Quote: "`AggregateStoreTests` stays, adapted to the new store types"; "All three stores use it, the in-memory store included"; "the bus tests build it from the mappings they need through `TestMessages`".
Consequence: the test's own events (`AggregateStoreTests$CounterEvent$...`) are in a package no module mapping trusts, so every read would throw and subscriptions would pass over them; `CommandHandlerTests` has the same gap.
Belongs to: spec
Resolution: fixed in r5: tests with their own test-only message classes build a `MessageMapping` through `TestMessages` that trusts the test's own package.
