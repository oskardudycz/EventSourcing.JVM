### Step-1. Dead-letter publish is not awaited

Quote: earlier finding. In Spring Kafka 4.1.2 the `DeadLetterPublishingRecoverer` constructor sets `failIfSendResultIsError = true`, with `waitForSendResultTimeout` 30s, and `publish` calls `verifySendResult`. New test `messageIsNotLostWhenTheFirstDeadLetterPublishFails` injects `FailingFirstSendKafkaTemplate` as the dead-letter template and asserts one record in `billing-dlt` and `deadLettered() == 1`.
Consequence: a failed send makes `deadLetters.accept` throw, so the counter does not rise and the offset is not committed. The claim holds and the test fails if the failure were swallowed.
Belongs to: implementation
Resolution: fixed

### Step-2. 11.1 does not time the forwarder's publish

Quote: plan 11.1: "assert the forwarder's publish fails within the publish timeout plus one second and its checkpoint is unchanged". `forwarderPublishFailsWithinTheTimeoutAndKeepsItsCheckpointWhileKafkaIsDown` waits for `publishAttempts.get() >= 2`. Timing is only in `publishFailsWithinThePublishTimeoutWhileKafkaIsDown` on a direct publish. Unchanged.
Consequence: the test passes if each forwarder publish blocks long, as long as it retries twice.
Belongs to: implementation
Resolution: accepted by the coordinator under Q30: a paused broker can't show the producer dropping a request already in the socket; the timeout sizing is checked on the producer configuration and the direct publish is timed.

### Step-3. The `messaging.dead_lettered` tags are unbounded and not in the spec

Quote: `.counter(DEAD_LETTERED, "message.type", typeNameOf(record), "messaging.destination.name", record.topic())`; `typeNameOf` returns the raw header. Spec 247 names no tags. Unchanged.
Consequence: a sender-chosen header value creates a Micrometer series per value, so the registry can grow without bound. `messaging.destination.name` is the channel topic for a `#` queue and the queue topic otherwise. No test checks the tags.
Belongs to: implementation (bound the tag), with a spec gap on the tag set. Neither spec.md nor qa.md names tags.
Resolution: decided by the coordinator under Q30, following the workshop's counter ("tagged with the message type and the source topic or queue"): tag `message.type` with the registered stable name, or `unknown` when the header names no registered type, so the series stay bounded; keep the source topic tag.

### Step-4. A type name in the trusted package that names no class has no test

Consequence: the "unknown" half of plan 19 is now guarded. Note: unlike the two sibling tests, it does not assert `deliveryAttemptOf == 1`, so a retry before dead-lettering would go unseen. This is not reported as a finding.
Belongs to: implementation
Resolution: fixed

### Step-5. `typeNameOf` falls back to the Java class name

Quote: `mapping.typeNameOf(messageClass).orElseGet(messageClass::getName)`, pinned by `aMessageWithoutAStableTypeNameIsWrittenUnderItsClassName`. Spec 253: "Every message type that crosses the bus has a stable type name in the mapping." Unchanged.
Consequence: an unmapped class is published under its Java name, so a class rename breaks old messages. The spec does not say what happens to an unmapped type.
Belongs to: spec
Resolution: decided by the coordinator under Q30, from spec "Every message type that crosses the bus has a stable type name in the mapping" and Q19/Q20's explicit, intentional routing: publishing a type with no stable name fails with an error naming the type; a test checks every type the modules publish has a stable name.

### Step-6. The Spring bean wiring of the dead-letter template and retry interval has no test

Quote: `deadLetterKafkaTemplate` only calls `setObservationEnabled(true)`; `TestKafka` sets `setObservationRegistry(observations)` by hand; `ECommerceSettingsTests` checks only the bus type. Unchanged.
Consequence: test 17.2 stays green even if the production bean has no registry, so dead letters may go untraced in the real application.
Belongs to: implementation
Resolution: implementation; add a Spring context test with `messaging.bus=kafka` that checks the dead-letter template bean has the observation registry and the retry interval comes from the property.
