### Step-1. The bus passes `correlationId` and `messageId` to its subscribers without a test
Quote: `InMemoryMessageBus`: `var values = context.inheritForPublished(message.getClass(), position); ... try (var _ = context.handling(values.messageId(), values.correlationId()))`. `InMemoryMessageBusTests` has no test of the five values. The 35.1 and 35.2 tests assert only `causationId`. `aHandledMessagePassesItsCorrelationIdOnAndBecomesTheCause` covers the store subscriber path only. Step: "a message with no handled message gets a random UUID".
Consequence: a bus that passes a new `correlationId`, or a non-random `messageId` for a publish outside a handler, passes every test. The flow's `correlationId` could break at each bus hop unseen.
Belongs to: implementation
Resolution: fixed after the review by the implementer (`InMemoryMessageBusValuesTests`); re-review requested.

### Step-2. The HTTP part of an extra test is not tested
Quote: plan: "aStepWithNothingToInheritGeneratesTheCorrelationId - events appended by an HTTP command have a new `correlationId` and `causationId` equal to it". The test calls `eventStore().append(...)` directly. No test under `api/` reads `correlationId` or `causationId`.
Consequence: the real request path (server span, `management.tracing.baggage.remote-fields`) is unchecked, for both the generate-new case and an inbound `baggage` header.
Belongs to: implementation (or change the plan wording to "an append with no handled message")
Resolution: sent back to the implementer: add the HTTP-level test the plan names, through the API on the `in-memory` profile.

### Step-3. Metadata that is not a JSON object throws out of KurrentDB `read` and the subscription
Quote: `EventSerializer.userMetadataOf`: `mapper.readValue(raw, new TypeReference<Map<String, Object>>() {})`. `KurrentDBEventStore.read` catches only `InterruptedException | ExecutionException`. Tests cover empty metadata and non-string values, not non-object metadata. Neither spec.md nor qa.md says what to do.
Consequence: an event written by another writer with non-object metadata throws a Jackson exception out of `read` (an aggregate load fails) and stops a subscription. The behaviour (skip, fall back to ids, or fail) is undecided. Low severity.
Belongs to: spec
Resolution: decided by the coordinator under Oskar's standing instruction (Q30), consistent with the step's own fallback rule for non-string values: metadata that is not a JSON object is treated as no metadata, so `read` and the subscription don't fail on it; sent back to the implementer with a test.

### Standards-1. `MessageContext.untraced()` is a test-only factory in production code
Quote: `public static MessageContext untraced() { return new MessageContext(Tracer.NOOP); }`; no caller in `src/main`; about 45 test sites use `new InMemoryEventStore(MessageContext.untraced())` and `new InMemoryMessageBus(MessageContext.untraced())`. AGENTS.md: "Prefer simple, easily removable code over premature abstractions."
Consequence: one extra production entry point used only by tests. Tests built with it run without baggage, so they do not test propagation. Behaviour is correct; low severity, a design call. The no-arg constructors from the first review are gone.
Belongs to: implementation
Resolution: sent back to the implementer: move `MessageContext.untraced()` into test code.
