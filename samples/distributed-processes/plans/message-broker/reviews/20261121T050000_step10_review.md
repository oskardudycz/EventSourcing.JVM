### Step-1. No test publishes successfully to a requests or internal channel with a queue bound

Quote: `MANDATORY_CHANNEL_SUFFIXES = Set.of("-requests", "-internal")`; only `publishToAChannelOfRequestsWithNoQueueFails` uses such a channel.
Consequence: a mandatory template that wrongly fails routable messages would pass every step 10 test.
Belongs to: implementation
Resolution: fixed: `commandsToChannelsOfRequestsAndInternalMessagesWithAQueueAreHandled`.

### Step-2. The type-header test does not show what happens to the bad message

Quote: `messageWithoutATypeHeaderIsSkippedAndTheNextMessageIsHandled`; `queueListener` throws `UnreadableMessageException`, with no error handler.
Consequence: the name claims "skipped", but the bad message is requeued until the delivery limit; step 11 owns dead-lettering (18.1).
Belongs to: implementation
Resolution: fixed: renamed to `aMessageWithoutATypeHeaderDoesNotStopTheNextMessageFromBeingHandled`.

### Step-3. The settings test can pass on exchanges left by earlier runs

Quote: `exchangeNames()).contains("payments-requests", ...)`.
Consequence: a broker that already holds the exchanges hides a bus that no longer declares them.
Belongs to: implementation
Resolution: rejected: the Kafka settings test has the same limit, and deleting the real exchanges would harm a developer's Docker Compose RabbitMQ. The bus's own declaration is tested with unique names in `RabbitMQMessageBusTests`.

### Step-4. `awaitConfirm` nack and interrupt branches have no test

Quote: `if (!confirm.ack()) throw ...`; `catch (InterruptedException e)`.
Consequence: those branches never run.
Belongs to: implementation
Resolution: rejected: a broker nack needs a failing broker, and the plan lists neither case. The Kafka interrupt case was tested because the Kafka client throws its own exception there.

### Step-5. The restart test closes the bus, not the broker or the context

Quote: `beforeRestart.close()` in `waitingMessagesAreHandledAfterARestart`.
Consequence: durability is shown by the queue surviving a bus restart, not a broker restart.
Belongs to: implementation
Resolution: rejected: the plan says to close the context and start a new one; the bus is the part of the context that holds the connection. A broker restart is not in the plan.

### Step-6. Step 11 lists the publisher connection as new work

Quote: `publisher.setUsePublisherConnection(true)` in `RabbitMQMessageBus`; plan step 11 "Publishers use their own connection".
Consequence: step 11 repeats a sentence that is already true.
Belongs to: plan
Resolution: fixed in plan r6 by the coordinator: step 10 now names the publisher connection; step 11 only proves 21.1.
