### Step-1. Blank and differently cased setting values fail the start

Quote: implementer's outcome: "Blank values (`messaging.bus=`) and different case (`In-Memory`) fail start-up as unknown values. The spec does not say either way."
Consequence: A developer who writes `messaging.bus=Kafka` gets a start failure. Criterion 5.1 covers "a value outside its allowed values" but does not say whether matching ignores case.
Belongs to: spec
Resolution: accepted by the coordinator (Q30): values match exactly; a wrong case or a blank value stops the start and the error names the allowed values, so nothing runs on a wrong setting.
