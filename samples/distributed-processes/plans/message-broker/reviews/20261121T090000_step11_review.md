### Standards-1. `messagesIn` returns -1 for a missing field, and the outage test uses two counters

Quote: `RabbitMQManagement.messagesIn`: `queue(queue).get("messages") instanceof Number messages ? messages.intValue() : -1;`. In `RabbitMQMessageBusDeadLetterOutageTests` lines 82-83: `assertThat(management.messagesIn(orders)).isEqualTo(1)` inside `await().during(Duration.ofSeconds(7))`; line 88: `queues.messageCount(deadLetterQueue) == 2`.
Consequence: the management API reports `messages` on its stats interval (5 s by default), so a point-in-time read can be old, and a short gap where the field is missing returns -1. Inside `during(7 s)` one such read fails the test with "expected 1 but was -1" and no cause. `queues.messageCount` reads the exact count over AMQP, so the test has two sources for one fact. Low impact.
Belongs to: implementation
Resolution: fixed. `RabbitMQManagement.messagesIn` throws an `AssertionError` that names the queue when the management API has no count yet (so `untilAsserted` retries and a real failure shows the cause). The outage test reads the exact dead-letter queue count over AMQP (`queues.messageCount`); the source queue keeps the management count, because the AMQP count does not include a message that waits for dead-lettering.

### Standards-2. The `AmqpException` catch in the blocked-publisher test can still hide a failed publish

Quote: `catch (AmqpException publishFailedBecauseItWasBlocked) { return; }` in `publishWhileBlocked`.
Consequence: a nack or an unroutable-message error of the second publish is also an `AmqpException`. It ends the thread at once, and the test fails only after the 30 s wait in `isPublishingBlocked`, with no cause. The test still fails, so no case is missed. `assertThatThrownBy` does not fit, because the publish may end by interrupt or by timeout. Low impact.
Belongs to: implementation
Resolution: fixed. `RabbitMQMessageBusBlockedPublisherTests` keeps the `AmqpException` of the second publish in an `AtomicReference` and rethrows it as the cause of an `AssertionError` when the wait for the blocked connection times out.
