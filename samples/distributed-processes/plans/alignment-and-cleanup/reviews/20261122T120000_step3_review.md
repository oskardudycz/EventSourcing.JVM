### Step-1. closingAStoreReturnsOnlyAfterItsSubscriptionStopped cannot fail

Quote: `close(store); var attemptsAtClose = attempts.get(); assertThat(attempts).hasValue(attemptsAtClose);`
Consequence: it passes even if `close()` returns while a handler runs.
Belongs to: implementation
Resolution: fixed. New test `closingAStoreWaitsForTheHandlerThatIsRunning`: the handler blocks on a latch, `close()` runs on another thread, and it must return only after the handler finished.

### Step-2. 17.2 tests do not put the queue's module before the channel's module

Quote: the tests used one hand-made channel and queue.
Consequence: they do not show that a queue on another module's channel works whatever the order.
Belongs to: implementation
Resolution: fixed. Both tests build the bus from `PaymentsConfig` routes and channels and `OrdersConfig.ordersPaymentsResponsesQueue()`, and publish a `PaymentAuthorized`.

### Step-3. awaitProcessed for a checkpoint handled before a restart times out

Consequence: a restarted subscription has no progress until a new event is handled.
Belongs to: implementation
Resolution: fixed. The PostgreSQL subscription seeds its progress from the stored checkpoint on its first poll; the KurrentDB store seeds it when it subscribes. Test `awaitingACheckpointHandledBeforeARestartReturnsAfterTheRestart`.

### Step-4. New beans paymentTerms, paymentValidity, isProductAvailable

Belongs to: implementation
Resolution: accepted by the coordinator as module-owned settings beans.
