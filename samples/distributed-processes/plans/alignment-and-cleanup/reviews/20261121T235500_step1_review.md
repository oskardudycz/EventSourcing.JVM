## Standards

Checked: the diff against `AGENTS.md` (test naming from the user's perspective, AssertJ, no mocks, no comments, README Java blocks, Markdown paragraphs on one line) and against the code around it: `ShopPages`, `ShopPagesTests`, `RandomProductPriceCalculatorTests`, the other Thymeleaf templates, and the existing `statusOf` helper in `ShopPages`.

### Standards-1. `orderStatus` copies the lookup of `statusOf`

Quote: new code `orderStatuses.get(new OrderId(Urns.of("ecommerce", "order", orderId)))` followed by `.filter(order -> order.getCustomerId().equals(customerId)).orElseThrow(... NOT_FOUND ...)`. The existing `private OrderStatus statusOf(UUID customerId, String orderId)` at line 231 still serves `cancel` and `retryPayment`, and runs the same lookup and the same 404.
Consequence: the "not found" rule is now written twice in one class. A later change to the rule, such as a different 404 message, must be made in both places. The match with the `local conventions` rule is weak, because the plan names no way to split the lookup; this is a duplication finding only.
Belongs to: implementation
Resolution: fixed: `orderStatusOf` holds the lookup; `statusOf` keeps the single 404.

### Standards-2. The "once it has a status" test asserts on text that the placing page also has

Quote: test `orderPageShowsTheOrderOnceItHasAStatus`: `containsString("Order status")` together with `matchesPattern("(?s)(?!.*Your order is being placed).*")`. `order-placing.html` has `<h1>Order status</h1>`.
Consequence: the first assertion passes on the placing page too. The test still fails correctly because of the second assertion, so no wrong behaviour passes. A check on a text that only the real page has, such as a product name, would read more clearly. This is a clarity finding.
Belongs to: implementation
Resolution: open
