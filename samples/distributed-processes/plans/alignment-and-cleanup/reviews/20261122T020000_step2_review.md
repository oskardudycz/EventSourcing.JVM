### Step-1. A negative client version now means `at(-1)` and differs per store
Quote: `ShoppingCartFacade` passes `ExpectedStreamVersion.at(command.expectedVersion())`; before, a negative version became `noStream`.
Consequence: a client that sends `W/"-1"` gets a different result on each store; the edge is hard to reach.
Belongs to: plan
Resolution: fixed: follow-up F1, option A. `ExpectedStreamVersion.at(n)` accepts only `n >= 0` (`ExpectedStreamVersionTests`); `CommandHandler` answers a negative client version with `ConcurrentModificationException` before it decides (`CommandHandlerTests.aNegativeClientVersionIsAConflictAndDecidesNothing`), so the API answers 412 (`CheckOutShoppingCartTests.checkOut_fails_withPreconditionFailed_forANegativeVersionInIfMatch`).

### Step-2. Appending zero events differs by store
Quote: `v_count := array_length(v_messages_data, 1)` is NULL for an empty array; the in-memory store returns `Success(-1, ...)`.
Consequence: same call, different results; no caller reaches it (`AggregateStore` guards it).
Belongs to: plan
Resolution: fixed: follow-up F2, option A. `append` throws `IllegalArgumentException` for zero events on the three stores (`EventStoreTests.appendingNoEventsIsRefusedAndCreatesNoStream`).

### Step-3. Untested append paths
