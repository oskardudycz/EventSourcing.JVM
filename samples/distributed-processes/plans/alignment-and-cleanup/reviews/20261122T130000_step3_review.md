### Step-R1. The saga-after-forwarders order is not tested through the Spring wiring

Quote: `OrdersConfig.orderSagaSubscriptions` returns `() -> subscribeOrderSaga(eventStore, messageBus)`; `ECommerceTests` calls the bean methods itself and subscribes the saga last. Spec: "`OrdersConfig` subscribes it from a `SmartInitializingSingleton` bean ... Test wiring in plain Java calls the same method last." and 17.3: "This protects existing behaviour (`ECommerceTests`)."
Consequence: if the saga were subscribed as a plain bean, or before the forwarders, in the running application, no test would fail. The test's own call order protects 17.3.
Belongs to: implementation. The spec decides that `ECommerceTests` with plain Java wiring is the guard, so the code follows it. A Spring-level check (for example in `ECommerceModulesTests`) would be an addition for Oskar to accept or reject.
Resolution: fixed: `OrderSagaSubscriptionOrderTests.theOrderSagaSubscribesToTheEventStoreAfterEveryExternalEventForwarder` starts the in-memory application with a recording `EventStore` fake and asserts that `order-saga` is the last store subscription after the three forwarders.
