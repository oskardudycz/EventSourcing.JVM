### Q&A-1. `AggregateStore` calls `continueTraceOf`, which the spec removes from `EventStore`

Quote: "`continueTraceOf` leaves the interface"; "`AggregateStore` uses `ExpectedStreamVersion` and the new results".
Consequence: `getAndUpdateContinuingTrace` (`AggregateStore.java:39-48`) no longer compiles; only the shop calls it; delete or rewrite is a guess.
Belongs to: spec
Resolution: fixed in r4 (coordinator, under Q11 "only align what's needed in core"): the methods only the shop used (`getAndUpdateContinuingTrace`, `getAndUpdate(id, expectedVersion, handle)` and its helpers) are deleted; `get(id)` and `getAndUpdate(id, handle)` stay.

### Q&A-2. `AggregateStore` stays and changes, but its tests are deleted

Quote: "`CommandHandlerTests` on the in-memory store, which replaces `AggregateStoreTests`"; "they stay in core ... adapted to the new event store types only".
Consequence: the only tests of a kept, changed class would be deleted.
Belongs to: spec
Resolution: fixed in r4: `AggregateStoreTests` stays, adapted, minus the tests of the deleted methods; `CommandHandlerTests` is new.

### Quality-2. Kept `EntityStore` on `MessageSerializer`: read behaviour and type mapping are not stated

Quote: "`EntityStore` uses `MessageSerializer` instead of the deleted `EventSerializer`"; "A stream read that meets an event it can't map fails"; "Only `KurrentDBEventStore` converts to `StreamState` and `Position`".
Consequence: today `EntityStore` passes over events it can't read, `MessageSerializer.read` throws; no mapping trusts the hotel packages; `EntityStore` keeps the raw KurrentDB client and its `StreamState` conversion.
Belongs to: spec
Resolution: fixed in r4: `EntityStore` takes a `MessageSerializer` in its constructor from whoever creates it (nothing creates it today), keeps its raw KurrentDB client and its own `StreamState` conversion, and keeps passing over events it can't read, as now. The "fails on an unreadable event" rule and "only `KurrentDBEventStore` converts" apply to the three `EventStore` implementations. No test, as no test covers `EntityStore` today (Q11).
